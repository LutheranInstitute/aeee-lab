# Repository to business preparation

## Establish the owner first

Check the connected GitHub account before asking the person to log in. Reuse an authenticated session and verify login and destination permissions. If not connected, offer the supported GitHub connection or official OAuth flow before the first business question; allow the person to continue with a private draft if they prefer.

Use CLI.LLC branding for preparation without replacing the entrepreneur's own identity. Treat sign-in, destination selection, repository visibility, and authorization to mutate as distinct decisions. Never equate a public source template with consent to publish interview answers.

## Choose the copy honestly

| Situation | Preferred preparation | Describe it as |
|---|---|---|
| Another user's starter; supported fork action | Fork into the verified principal's account | Independent fork |
| Template source; supported creation action | Create from template in chosen destination | Template-derived repository |
| Principal owns the source; isolated work is sufficient | Separate branch or isolated checkout | Branch copy or local checkout |
| No supported remote copy mechanism | Prepare a reviewable artifact with source provenance | Prepared artifact; remote copy pending |

Do not silently substitute a branch if the user explicitly requires a separate repository. Before a fallback, determine whether another supported connector or CLI can satisfy the request. Do not probe browser sessions without explicit site intent or permitted fallback. Resolve a real access blocker before claiming completion.

## Configuration essentials

Use existing schema conventions, or write a small JSON object with:

- Principal and project display name; legal entity name separately and nullable.
- Purpose, optional domain, and personal glyph.
- Source repository, exact revision, and copy mechanism.
- Real provider links and verification statuses.
- Formation, payments, deployment, and runtime states, initially pending unless evidence confirms otherwise.
- Separate NAICS, IRS activity-code, legal/tax-status, and bookkeeping records with source edition, filing year where relevant, rationale, and review status; keep private interview evidence outside public files.

Use public identity only when appropriate to the destination. Do not collect SSN, ITIN, API keys, banking details, or private founder documents into chat or public configuration.

## Resume instead of duplicating

Inspect the existing configuration, branch, and provider status. Continue from checked progress. Do not resubmit an operation because a previous turn lost its result. Record provenance and a concise receipt after changes.

Keep receipts truthful: advertised capability is not implemented capability; a file in the repository is not a live deployment; a branch is not independent ownership; a submitted filing is not a formed company.
